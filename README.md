Анализатор подозрительности URL
Сайт доступен по адресу: [https://url-analyzer-k1lf.onrender.com](https://url-analyzer-k1lf.onrender.com)

Локальный запуск
1. Клонируйте репозиторий: `git clone https://github.com/urlanalyzer95/url-analyzer.git`
2. Установите зависимости: `pip install -r requirements.txt`
3. Переобучите модель (опционально): `python train_model.py`
4. Запустите сервер: `python -m app.server`
5. Откройте в браузере: `http://127.0.0.1:5000`

Технологический стек
- Backend: Python 3.10, Flask, Gunicorn
- ML: scikit-learn (Random Forest), pandas, numpy, joblib
- Database: SQLite (отзывы пользователей)
- Frontend: HTML, CSS, JavaScript (адаптивный дизайн)
- Deployment: Docker, Render (также возможен локальный запуск)

ML-часть проекта: описание, данные, признаки, модель и результаты

1. Источник данных
Датасет взят с Kaggle: https://www.kaggle.com/datasets/hassaanmustafavi/phishing-urls-dataset?resource=download
Phishing URLs Dataset (автор: Hassaan Mustafavi).

Подготовка данных:
- Исходный датасет очищен от дубликатов, пропусков и невалидных URL.  
- Вручную добавлены известные доверенные домены (google.com, yandex.ru, github.com и др.) с меткой `legitimate`.  
- Добавлены опасные примеры (IP-адреса, сервисы сокращения ссылок) с меткой `phishing`.  
- Проведена балансировка классов (50/50).  
- Итоговый датасет содержит 208 788 URL и 14 числовых признаков.

Почему выбран именно этот датасет?
Достаточно большой объём (более 200 тыс. примеров) – позволяет обучить модель, устойчивую к переобучению.
Чистая разметка (только два класса).
Содержит разнообразные URL: от обычных сайтов до сложных фишинговых конструкций.
Датасет популярен в задачах обнаружения фишинга, что позволяет сравнивать результаты с другими работами.
Дополнительно датасет был расширен вручную добавлением известных доверенных доменов и опасных примеров. Это сделано для повышения качества модели на «краевых» случаях.

2. Изученные источники и статьи
При разработке модели изучались следующие работы:
“Phishing URL Detection using Machine Learning” (Sahingoz et al., 2019) – обзор признаков на основе лексического анализа.
“Detecting Phishing Websites through Machine Learning” (Jain, Gupta, 2018) – сравнение Random Forest, SVM, XGBoost.
“Lexical Features for Phishing URL Detection” (Marchal et al., 2016) – описание признаков: длина URL, количество точек, слешей, наличие IP, подозрительные слова.
Документация scikit-learn по Random Forest и XGBoost.

3. Почему выбраны именно такие признаки?
Мы выделили 14 признаков, которые часто встречаются в литературе и имеют высокую предсказательную силу:

| Признак       | Обоснование                                                                            |
| ------------- | -------------------------------------------------------------------------------------- |
| url_length    | Фишинговые URL часто длиннее (много вложенных каталогов, параметров).                  |
| num_dots      | Много точек → попытка скрыть реальный домен (paypal.com.attacker.com).                 |
| num_hyphens   | Дефисы маскируют домен (secure-pay-pal.com). jcsdf.nfsu                                |
| num_slashes   | Глубокие пути увеличивают длину (/login/secure/verify/).                               |
| num_params    | Параметры ? и & типичны для фишинга (?session=abc&redirect=evil).                      |
| has_ip        | IP-адрес вместо домена – почти всегда фишинг (185.13.55.2).                            |
| has_https     | Фишеры используют бесплатные SSL (Let's Encrypt), признак полезный, но не решающий.    |
| has_login     | Ключевые слова login типичны для фишинговых страниц.                                   |
| has_verify    | verify/account/admin – маркеры фишинга.                                                |
| has_account   | account/admin – подозрительные термины.                                                |
| has_admin     | admin/cp.php – панели управления.                                                      |
| has_cp.php    | .php файлы админок часто фишинговые.                                                   |
| is_shortened  | bit.ly/tinyurl маскируют фишинг.                                                       |
| domain_length | Длинные поддомены редко у легитимных сайтов.                                           |

Почему не добавили другие признаки (возраст домена, WHOIS, черные списки)?
Эти данные требуют внешних запросов (снижают скорость, усложняют инфраструктуру).

Мы решили начать с чисто лексического анализа, который работает быстро (<10 мс на URL).

4. Почему выбрали Random Forest, а не другую модель?
На основе анализа литературы Random Forest является одним из лучших алгоритмов для задач классификации URL. Основные причины выбора:
Высокая точность – Random Forest стабильно показывает 97-99% accuracy на подобных датасетах.
Интерпретируемость – можно вычислить важность признаков и объяснить пользователю, почему ссылка опасна (например, «слишком длинная», «содержит слово login»).
Скорость – предсказание за 3-10 мс на CPU, что критично для веб-сервиса.
Устойчивость к переобучению – ансамбль деревьев решений хорошо обобщается на новых данных.
Не требует GPU – легко развернуть на любом хостинге.

Альтернативные модели (XGBoost, LightGBM, нейронные сети) потенциально могут дать немного более высокую точность (до 99%), но требуют более тщательной настройки гиперпараметров и могут быть медленнее при предсказании. В следующем спринте мы планируем экспериментально сравнить Random Forest с XGBoost на нашей выборке.

5. Подробный анализ результатов
Модель Random Forest обучена на 208 788 URL (сбалансированные классы). Тестирование – 20% выборки (41 758 URL).
Общая точность (accuracy): 98.13%

Метрики по классам:

| Класс       | Precision | Recall | F1-score | Support |
|-------------|-----------|--------|----------|---------|
| Легитимный  | 0.96      | 1.00   | 0.98     | 20 887  |
| Фишинговый  | 1.00      | 0.96   | 0.98     | 20 871  |

Топ-5 важных признаков:
1. `has_https` – 0.776
2. `num_dots` – 0.094
3. `has_login` – 0.028
4. `domain_length` – 0.026
5. `num_hyphens` – 0.023

Сильные стороны: высокая точность, отсутствие ложных срабатываний, скорость <10 мс, интерпретируемость.
Слабые стороны: пропуск ~4% фишинга, сильная зависимость от `has_https`.

6. Заключение
Разработанная ML-модель достигла точности 98.1% на тестовой выборке. Выбор признаков и модели основан на анализе научных статей и практическом опыте. Модель успешно интегрирована в веб-сервис и используется для проактивного выявления фишинговых URL. Дальнейшее развитие будет направлено на устранение ложных срабатываний и добавление новых источников данных.

7. Распределение ролей в проекте

- Роль 1 (ML-инженер):разработка модели Random Forest, извлечение 14 признаков из URL, обучение на 208 788 записях, оценка точности (98.13%).
   
- Роль 2 (Data-инженер): сбор, очистка, балансировка и версионирование датасета; добавление доверенных и опасных примеров; настройка базы данных SQLite для сбора отзывов.
  
- Роль 3 (Старший интегратор): разработка Flask-сервера с API (`/check`, `/feedback`, `/download-db`); интеграция ML-модели в веб-сервис; реализация кэширования (24 часа); деплой проекта на Render; оказание поддержки Роли 1 в доработке ML-логики (исправление ошибки размерности входных данных, настройка порогов классификации для вывода вердикта).  

- Роль 4 (Младший интегратор): создание адаптивного веб-интерфейса (HTML/CSS/JS); разработка футера; реализация страницы админ-панели (`admin.html`) с пагинацией для просмотра отзывов; добавление анимации загрузки и формы обратной связи.
